Searching a maze with no map and no hints.

A blind search agent can only do two things: see which moves are available right now, and check if it has arrived. Everything on this site shows, live and step by step, how four classic strategies do exactly that.

The core idea

One loop. Four personalities.

Every blind search runs the same loop: pick a node from the frontier, test it, expand it. The ONLY thing that changes between strategies is which node leaves the frontier next. That choice is made by one data structure.

// the generic search loop
frontier ← { initial state }

loop:
    if frontier is empty → return FAILURE
    node ← remove ONE node from frontier
    if node is goal → return solution
    add node's children to frontier

🚶 Queue → Breadth First

BCD← oldest leaves first

Like a line at a shop. Whoever joined first is served first. The search spreads level by level, like a wave.

🍽 Stack → Depth First

DCB← newest leaves first

Like a stack of plates. You always take the one you just placed. The search dives deep, then backtracks.

Breadth First Search

Expand the shallowest unexpanded node first. Finish an entire level before touching the next one, like a wave of water spreading across a map.

COMPLETE: YES*OPTIMAL: YES (unit costs)TIME: O(b^d)SPACE: O(b^d)

AThe idea

New children are added to the back of a FIFO queue, and the next node always comes from the front. Older nodes are always shallower, so the tree is explored level by level: root, then all depth 1 nodes, then all depth 2 nodes, and so on.

BWhy it is complete and optimal

  • Complete: every shallower level is exhausted first, so the shallowest goal is guaranteed to be reached (if b is finite).
  • Optimal only when all step costs are equal. Then fewest steps means lowest cost. With different step costs, a short path can still be expensive, and BFS does not see that.

CThe memory wall

BFS keeps every generated node in the queue. With b = 10 and a goal at depth 12, the deepest level alone holds about 1012 nodes. At 1 KB each, that is roughly a petabyte. In practice, BFS runs out of memory long before it runs out of time.

Rule of thumb: use BFS only when solutions are shallow and the space is small enough to fit in RAM.

Depth First Search

Expand the deepest unexpanded node first. Commit to one path, follow it to the bitter end, then backtrack and try the next branch.

COMPLETE: NOOPTIMAL: NOTIME: O(b^m)SPACE: O(b·m)

AThe idea

Children are pushed onto a LIFO stack, so the newest node is always expanded next. The search plunges downward. When it hits a leaf or a dead end, it pops back up to the most recent node that still has unexplored children. That return trip is called backtracking.

BWhy it is dangerous

  • Not complete: in an infinite tree, or in a graph with cycles and no explored set, DFS can descend forever and never try the other branches.
  • Not optimal: it can return a deep, expensive goal while a shallow, cheap one waits on another branch.
  • Time O(b^m): terrible when m is much larger than d.

CWhy we still love it

Memory. DFS stores only the current path plus unexpanded siblings: O(b·m). For b = 10 and m = 12 that is about 120 nodes, where BFS would hold 1012. DFS is also the skeleton of backtracking search, constraint solvers, and many graph algorithms.

Variant: backtracking search generates one child at a time and edits the state in place, shrinking memory toward O(m).

DFS + a safety rail

Depth Limited Search

DFS with a depth limit l. Nodes at depth l are treated as if they had no children, so the search can never fall down an infinite hole.

COMPLETE: ONLY IF l ≥ dOPTIMAL: NOTIME: O(b^l)SPACE: O(b·l)

AThe two different failures

DLS is the first strategy that can report two distinct non answers, and the difference matters:

  • FAILURE means: I searched this entire subtree and there is definitely no solution in it.
  • CUTOFF means: I stopped because I hit the depth limit. A solution might still exist deeper.
DLS(node, goal, limit):
  if node is goal → return SOLUTION
  else if limit = 0 → return CUTOFF
  else:
    cutoff_occurred ← false
    for each child of node:
      result ← DLS(child, goal, limit − 1)
      if result = CUTOFF → cutoff_occurred ← true
      else if result ≠ FAILURE → return result
    return CUTOFF if cutoff_occurred else FAILURE

BThe guessing problem

If the limit is smaller than the true goal depth d, DLS misses the solution. If the limit is far too large, it degenerates back into slow DFS. Sometimes domain knowledge helps: on a map of 20 cities, a simple path never needs more than 19 moves, so l = 19 is safe. The diameter of the state space (longest shortest path between any two states) is the natural choice. Usually, though, you simply do not know d.

Try it in the lab: set the limit to 0, 1, 2 and watch the search get CUTOFF after CUTOFF. Then set it to 3 and watch it finally reach the goal K, which lives at depth 3.

Iterative Deepening Search

Do not guess the limit. Try them all. Run DLS with limit 0, then 1, then 2, and so on until a goal appears. BFS guarantees, DFS memory.

COMPLETE: YES*OPTIMAL: YES (unit costs)TIME: O(b^d)SPACE: O(b·d)

A"But is it not wasteful?"

Yes, nodes near the root get re expanded every iteration. But the waste is small because most nodes live at the bottom level. With b = 10 and d = 5:

  • BFS generates about 111,111 nodes.
  • IDS generates about 123,456 nodes.
  • Overhead: roughly 11%, and it shrinks as b grows.

The nodes at depth d are generated once, depth d−1 twice, and so on. The giant last level dominates the sum.

BThe verdict

IDS is the default choice for uninformed search when the space is large and the solution depth is unknown. It is complete, optimal for unit costs, and needs only linear memory. Watch the total expansion counter in the lab climb across iterations. That is the price, and it is a bargain.

Exam line to remember: "IDS gives BFS completeness and optimality at DFS memory cost, with only a constant factor of extra node generation."

Which one, when?

Decision cheat sheet

Shallow goal + plenty of RAM?

Use BFS. You get the fewest steps solution and you will not regret it until the memory bill arrives.

Tiny memory + solutions are deep?

Use DFS, ideally with an explored set and a backup plan for when it dives into a swamp.

You know a safe depth bound?

Use DLS with that bound, for example the diameter of a small map.

Big space, depth unknown?

Use IDS. It is the standard answer to "which blind search should I pick?"
