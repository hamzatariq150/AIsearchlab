Two big families

Systematic search vs local optimization

🗺 Systematic search (L4, L5)

The path to the goal matters. The agent builds a tree of possibilities and explores it in some order. BFS, DFS, A*. Great when you need the sequence of actions, like driving from Arad to Bucharest.

⛰ Local search (L6)

Only the goal state matters, not how you got there. Keep one current state and improve it. Hill climbing, simulated annealing, genetic algorithms. Great for n-queens and the travelling salesperson.

Lecture 1

Introduction to Artificial Intelligence

The big questions, four ways to define AI, the Chinese Room, the Turing Test, and a quick history.

AThe big questions

Can machines think. If so, how. If not, why not. And what does that say about human beings. AI is the study of technologies needed for implementing intelligent behavior in applications like computer vision, robotics, and expert systems.

BFour definitions of AI

Definitions fall into a two by two grid: thinking vs acting, and like humans vs rationally.

Think like humans

Cognitive modeling, how the mind works.

Think rationally

Laws of thought, correct reasoning.

Act like humans

The Turing Test approach.

Act rationally ★

Rational agents. This course follows this one.

Why "act rationally": it avoids philosophical issues like "is the system conscious". Acting rationally is broader than acting human, and if a machine can be more rational than humans in some domain, that is a win.

CThe Chinese Room argument

John Searle, 1980. A person who knows English but not Chinese sits in a room with a rule book. Chinese questions come in, the rule book tells the person which Chinese symbols to send back. From the outside, the room answers perfectly. But the person understands nothing. Searle argues the computer is the same. It manipulates symbols (syntax) without meaning (semantics).

Three common responses:

  • System response: the hardware alone is not intelligent, but hardware plus software plus storage together may be.
  • Robot response: a robot with sensors can tie symbols to the physical world and gain meaning.
  • Brain simulator response: if we mimic the brain, for example with a neural network, it may understand like a brain.

DThe Turing Test

A human judge talks to a human and a machine over a text only channel. Both try to act human. The judge guesses which is which. If the judge cannot tell, the machine passes. The Loebner Prize is a real competition based on this.

ELessons from AI research

  • Clearly defined tasks we think need intelligence, like chess or logical inference, tend to be doable. Scalability is the hard part.
  • Complex, messy, ambiguous tasks that feel easy to humans, like recognizing your grandmother in a crowd or driving in a city, are much harder for AI.
  • Humans are still better at adapting, self evaluation, and creativity.

FA quick history

  • Birth (1943 to 1956): McCulloch and Pitts model neurons. Turing proposes the Turing machine and test. Shannon studies chess.
  • Early enthusiasm (1952 to 1969): the 1956 Dartmouth conference. McCarthy invents Lisp. Newell and Simon build the General Problem Solver. Robinson introduces resolution.
  • Knowledge emphasis (1966 to 1974): domain knowledge is the key. Knowledge representation paradigms emerge.
  • Knowledge based systems (1969 to 1979): DENDRAL, MYCIN, PROSPECTOR.
  • AI becomes an industry (1980 to 1989): expert systems go commercial.
  • Current trends (1990 to present): practical goals, intelligent agents, neural networks, genetic algorithms, machine learning.

Lecture 2

Intelligent Agents

Agents and environments, rationality, PEAS, environment types, and agent architectures.

AWhat is an agent

An agent is anything that perceives its environment through sensors and acts on it through actuators. A human agent uses eyes and hands. A robot uses cameras and motors.

The agent function maps percept histories to actions. The agent program runs on physical architecture to produce that function. So agent = architecture + program.

BRationality

A rational agent selects the action expected to maximize its performance measure, given the percept sequence and built-in knowledge. Rationality depends on four things: the performance measure, prior knowledge, available actions, and the percept sequence so far.

Rational is not omniscient. Percepts may not give all information, like not seeing other players' cards. Rational is not perfect. Rationality maximizes expected outcome, perfection maximizes actual outcome.

Autonomy is how much the agent's behavior comes from its own experience rather than the designer's knowledge. A good agent has some autonomy and grows more with experience.

CPEAS

To design an agent, first specify the setting: Performance measure, Environment, Actuators, Sensors. Try the interactive PEAS explorer on the right.

DEnvironment types

Environments are described along six dimensions. Explore them in the classifier on the right.

  • Fully vs partially observable: do sensors give everything needed to choose an action.
  • Deterministic vs stochastic: does the next state depend only on current state and action.
  • Episodic vs sequential: does the current choice depend on previous actions.
  • Static vs dynamic: does the environment change while the agent is thinking.
  • Discrete vs continuous: a limited set of distinct percepts and actions, or a range of values.
  • Single vs multiagent: one agent or many.

EAgent types

Four basic types in order of increasing generality, and all can become learning agents.

  1. Simple reflex agents: act only on the current percept using condition-action rules. No memory. Can fall into infinite loops.
  2. Model based reflex agents: keep an internal state that tracks how the world evolves.
  3. Goal based agents: use knowledge about a goal to guide actions, through search and planning.
  4. Utility based agents: a utility function maps each state to a real number describing how good it is. Needed when many action sequences reach the goal.

Learning agents add a learning element, a critic, and a problem generator so the agent improves from experience and explores new actions.

Lecture 4

Problem Solving and Uninformed Search

Formulate a problem, then search for a sequence of actions. No hints about the goal allowed.

AProblem solving agents

A problem solving agent is a goal based agent. It decides what to do by finding sequences of actions that lead to desirable states. It works in a static, observable, discrete, deterministic environment, and it is an open-loop system that ignores percepts while planning.

Three steps: goal formulation, problem formulation, then search.

BFive components of a problem

  1. Initial state: for example, In(Arad).
  2. Actions: the moves available, for example Go(Sibiu), Go(Timisoara), Go(Zerind).
  3. Transition model: what each action does. Results(In(Arad), Go(Sibiu)) = In(Sibiu).
  4. Goal test: explicit, like In(Bucharest), or implicit, like checkmate.
  5. Path cost: a numeric cost per path, with step cost c(x, a, y).

A solution is a path from the initial state to a goal. An optimal solution has the lowest path cost among all solutions.

CProblem abstraction

The real world is full of detail. Abstraction removes irrelevant details from states and actions. A good abstraction is valid (it can be expanded into a real solution) and useful (its actions are easier to carry out than the original problem).

DClassic examples

  • Vacuum cleaner: 8 states, actions Left, Right, Suck, goal is both squares clean, each step costs 1.
  • Missionaries and cannibals: state is <m, c, b> for missionaries, cannibals, boat side. Start <3,3,1>, goal <0,0,0>, never let cannibals outnumber missionaries on either bank.

EStates vs nodes

A state is a representation of a physical configuration. A node is a data structure in the search tree holding state, parent, action, path cost g(n), and depth. The CHILD-NODE function builds a child node from a parent and an action.

FTree search vs graph search

The frontier holds leaf nodes available for expansion. A repeated state, a loopy path, or a redundant path wastes work. Failure to detect repeated states can turn a linear problem into an exponential one. Graph search adds an explored set that remembers every expanded node.

GThe uninformed strategies

Uninformed, or blind, search uses only the problem definition. Open each lab to drive the algorithm yourself.

HUniform cost search and bidirectional search

Uniform cost search expands the least-cost unexpanded node using a priority queue ordered by path cost g(n). It is optimal and complete if step cost is at least some epsilon. It equals BFS when all step costs are identical. Try it in the Playground.

Bidirectional search runs two searches at once, forward from the start and backward from the goal, and stops when they meet.

ISearching with partial information

  • Single-state: deterministic and fully observable. The agent knows exactly where it will be. Solution is a sequence.
  • Sensorless (multi-state): the agent has no idea where it is. Example: vacuum start in any of 8 states, solution Right, Suck, Left, Suck.
  • Contingency: nondeterministic or partially observable. Percepts give new information, so the agent interleaves search and execution. Solution is a tree or policy.
  • Online (exploration): states and actions are unknown and must be learned while acting.

Lecture 5

Informed Search and Heuristics

Blind search is a building block but very inefficient. Add knowledge about the goal and search smarter.

AInformed vs uninformed

An informed strategy uses knowledge beyond the problem definition. That knowledge lives in an evaluation function f(n). Uninformed search has no hint about the goal, so the plans differ only in order and length of actions.

Three famous evaluation functions:

  • Uniform cost: f(n) = g(n), the cost so far.
  • Greedy best first: f(n) = h(n), the estimated cost to the goal.
  • A*: f(n) = g(n) + h(n), both combined.

BThe heuristic function

A heuristic h(n) takes a node and returns a non-negative estimate of the cost of the cheapest path from n to a goal. It is a shortcut when exact solutions are too slow.

Admissible heuristic: h(n) never overestimates the true cost to reach the goal from n. Admissibility is what makes A* optimal.

CGreedy best first search

Expands the node estimated to be closest to the goal, f(n) = h(n). On the Romania map it uses straight line distance to Bucharest. It is fast but not optimal and not complete. It can get stuck going down a path and never return, for example looping Iasi to Neamt forever. Time and space are O(b^m), though a good heuristic can give dramatic improvement.

DHeuristics for the 8-puzzle

Average solution for a random 8-puzzle is about 22 moves with branching factor around 3. Two common heuristics:

  • h1 = number of misplaced tiles.
  • h2 = sum of distances of tiles to their goal position (Manhattan distance).

For one example state, h1 = 7 and h2 = 14.

EDominance

If h2(n) is at least h1(n) for all n, and both are admissible, then h2 dominates h1 and is better for search. Typical nodes expanded:

FRelaxed problems

Heuristics often come from a relaxed problem, where you remove constraints. The cost of an optimal solution to the relaxed problem is an admissible heuristic for the original.

  • Relax the 8-puzzle so a tile can move anywhere: h1 is the shortest solution.
  • Relax it so a tile can move to any adjacent square: h2 is the shortest solution.

You can also obtain heuristics from domain experts, from solving example problems, from learned evaluation functions, or by tuning parameters with machine learning.

GA* search

Greedy ignores how costly it was to reach a node. A* fixes this by combining both costs: f(n) = g(n) + h(n), the estimated cost of the cheapest solution through n. It avoids expanding paths that are already expensive.

  • If h(n) equals the true cost, only nodes on the correct path are expanded.
  • If h(n) is below the true cost (admissible), extra nodes are expanded but the optimal solution is still found.
  • If h(n) is above the true cost, the optimal solution can be overlooked.
Complete

Yes, unless infinitely many nodes have f at most f(G).

Time

Exponential in heuristic error times solution length. Best O(d) with a perfect h.

Space

Keeps all nodes in memory. Usually runs out of space before time.

Optimal

Yes. Cannot expand the next f level until the current one is done.

Lecture 6

Local Search and Optimization

When the path to the goal is irrelevant and only the goal state itself is the solution.

AThe idea

In many optimization problems, like reducing cost or reducing conflicts, we only care about the final state. Local search keeps a single current state and tries to improve it according to an objective function. It uses little memory and finds reasonable solutions in huge or infinite spaces. It is usually incomplete: it may stop even if the best solution found is not optimal, ending on a time bound or when no improvement is possible.

Examples: the travelling salesperson problem, where variants get within 1% of optimal for thousands of cities, and n-queens, which min-conflicts solves almost instantly even for n = 1 million.

BHill climbing

Also called greedy local search. Continually move in the direction of increasing value, uphill. Stop when you reach a peak where no neighbor is higher. It only records the current state and its value, and never looks ahead.

Two big problems:

  • Local maxima: a peak higher than its neighbors but lower than the global maximum. The algorithm climbs to it and gets stuck.
  • Plateaus: a flat area, either a flat local maximum with no uphill exit, or a shoulder where progress is possible.

If there are few local maxima, random-restart hill climbing finds a good solution very quickly. Try the landscape demo.

CSimulated annealing

To escape local maxima, sometimes take a random move. If the new state is better, move into it; otherwise accept it with some probability that shrinks over time. It terminates on an acceptably good solution in a fixed time, not necessarily the best. Widely used in VLSI layout and airline scheduling. Given infinite time it finds the global optimum, and it will not get stuck at a local optimum.

DGenetic algorithms

Inspired by evolution and natural selection. A successor is generated by combining two parents rather than modifying one state. Start with k random states, a population, where each is an individual represented as a string over a finite alphabet.

Each generation is produced by:

  1. Fitness evaluation: higher values for better states.
  2. Selection: pick parents with probability proportional to fitness.
  3. Crossover: pick a random point and combine the two parents.
  4. Mutation: flip genes with a small probability.

The 8-queens example uses strings of digits 1 to 8 for queen rows, and fitness = number of non-attacking pairs, from 0 up to 28. Probability of being selected is fitness divided by total fitness, for example 24/(24+23+20+11) = 31%.

FIFO queue frontier

Breadth First Search

Expand the shallowest unexpanded node first. Finish an entire level before touching the next, like a wave spreading across a map.

COMPLETE: YES*OPTIMAL: YES (unit costs)TIME: O(b^d)SPACE: O(b^d)

AThe idea

New children go to the back of a FIFO queue, and the next node always comes from the front. Older nodes are shallower, so the tree is explored level by level.

BWhy complete and optimal

  • Complete: every shallower level is exhausted first, so the shallowest goal is reached if b is finite.
  • Optimal only when all step costs are equal. Then fewest steps means lowest cost.

CThe memory wall

BFS keeps every generated node. With b = 10 and d = 12, the deepest level alone holds about 1012 nodes, roughly a petabyte at 1 KB each. BFS runs out of memory long before it runs out of time.

Rule of thumb: use BFS only when solutions are shallow and the space fits in RAM.

Depth First Search

Expand the deepest unexpanded node first. Commit to one path, follow it to the end, then backtrack and try the next branch.

COMPLETE: NOOPTIMAL: NOTIME: O(b^m)SPACE: O(b·m)

AThe idea

Children are pushed onto a LIFO stack, so the newest node is expanded next. When the search hits a dead end, it pops back up. That return trip is backtracking.

BWhy dangerous

  • Not complete: in infinite trees or graphs with cycles and no explored set, DFS can descend forever.
  • Not optimal: it can return a deep, expensive goal while a cheap one waits elsewhere.
  • Time O(b^m): terrible when m is much larger than d.

CWhy we still love it

Memory. DFS stores only the current path plus siblings: O(b·m). For b = 10 and m = 12 that is about 120 nodes where BFS holds 1012.

Backtracking search generates one child at a time and edits the state in place, shrinking memory toward O(m).

Note: DFS properties depend strongly on whether you use the tree-search or graph-search version. With an explored set, DFS becomes complete on finite spaces but loses its linear space advantage.

DFS + a safety rail

Depth Limited Search

DFS with a depth limit l. Nodes at depth l are treated as having no children, so the search can never fall down an infinite hole.

COMPLETE: ONLY IF l ≥ dOPTIMAL: NOTIME: O(b^l)SPACE: O(b·l)

ATwo different failures

  • FAILURE: I searched this whole subtree and there is definitely no solution.
  • CUTOFF: I stopped at the depth limit. A solution might exist deeper.
DLS(node, goal, limit):
  if node is goal → return SOLUTION
  else if limit = 0 → return CUTOFF
  else:
    cutoff_occurred ← false
    for each child of node:
      result ← DLS(child, goal, limit − 1)
      if result = CUTOFF → cutoff_occurred ← true
      else if result ≠ FAILURE → return result
    return CUTOFF if cutoff_occurred else FAILURE

BThe guessing problem

If l is smaller than the true depth d, DLS misses the solution. If l is far too large, it becomes slow DFS. The diameter of the state space is a natural choice for l. Try the limit buttons in the lab.

04
Repeated DLS, limits 0, 1, 2, ...

Iterative Deepening Search

Do not guess the limit. Try them all. Run DLS with limit 0, then 1, then 2, and so on until a goal appears. BFS guarantees, DFS memory.

COMPLETE: YES*OPTIMAL: YES (unit costs)TIME: O(b^d)SPACE: O(b·d)

A"But is it not wasteful?"

Nodes near the root are re-expanded each iteration, but most nodes live at the bottom level. With b = 10 and d = 5:

  • DLS to depth d generates 111,111 nodes.
  • IDS generates 123,456 nodes.
  • Overhead = (123,456 − 111,111) / 111,111 = 11%.

BThe verdict

IDS is the preferred uninformed search method when the search space is large and the solution depth is unknown. Complete, optimal for unit costs, linear memory.

Exam line: "IDS gives BFS completeness and optimality at DFS memory cost, with only a small constant factor of extra node generation."
